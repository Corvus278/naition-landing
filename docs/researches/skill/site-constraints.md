# Ограничения из site_dir

`site_dir` = корень репозитория `naition-low-conversion-landing`.

## Прочитанные файлы

- `STUDENTS.md` — студенческая инструкция: порядок работы (deploy → симулятор → анализ → правки → redeploy), явные списки «что можно менять» и «что нельзя менять (сломается симулятор)», проверка конверсии.
- `CLAUDE.md` — инструкция репозитория: описание архитектуры и раздел «Hard constraints (breaks the external simulator/analytics if changed)», дублирующий запреты `STUDENTS.md`; требование класть ресерчи в `/docs/researches`.
- `.cursor/rules/**` — отсутствует.
- Других markdown с правилами редактирования в `docs/` нет (кроме артефактов этого анализа).

Противоречий между `STUDENTS.md` и `CLAUDE.md` не найдено; `CLAUDE.md` дополнительно уточняет, что «Copy, styling, images, and in-section layout are fair game to edit».

## Можно менять

- Тексты, заголовки, описания (`STUDENTS.md`, «Что можно менять»).
- Цвета, шрифты, отступы, визуальное оформление.
- Изображения.
- Расположение элементов **внутри** секций.
- Видимость CTA через CSS — «но не удаляйте сами кнопки».
- `CLAUDE.md`: «Copy, styling, images, and in-section layout are fair game to edit».

Отсюда следует (толкование, применённое в работе):
- добавлять элементы **внутрь** существующих секций можно, переставлять секции местами и заводить новые секции — **нет** (строгое чтение «внутри секций»);
- `css/style.css` и `js/main.js` не входят в списки запретов, менять можно, пока сохраняются перечисленные ниже классы, поля и поведение кнопок.

## Нельзя менять

| Запрет | Источник |
|--------|----------|
| Форма `#registration-form` с `action="api/submit.php"` | STUDENTS.md, CLAUDE.md |
| Поля формы с именами `name`, `phone`, `email`, `purpose` | STUDENTS.md, CLAUDE.md |
| Скрытое поле `bot_session_id` | STUDENTS.md |
| `<script src="api/visit.php">` в `<head>` | STUDENTS.md, CLAUDE.md |
| Классы `.btn-register`, `.pricing-section`, `.program-module`, `.program-list` | STUDENTS.md, CLAUDE.md |
| PHP-файлы в `api/` и схема `sql/schema.sql` | STUDENTS.md, CLAUDE.md |
| `data/app.db` не коммитить | CLAUDE.md |

Уточнения по фактическому коду:

- **`bot_session_id`** в текущем `index.php` отсутствует, а `api/db.php` содержит миграцию, удаляющую эту колонку из `visits`/`orders` как legacy. Поле не добавляется и не удаляется — запрет соблюдается автоматически.
- **`api/submit.php` требует непустой `purpose`**: при пустом значении возвращает `{ok:false,"Укажите цель прохождения курса."}`. Значит нельзя просто сделать поле необязательным — нужно, чтобы значение проставлялось дёшево (быстрый выбор), но обязательность сохранялась.
- **Тип поля `purpose`** (сейчас `<textarea>`) не меняем: замена на radio/select — это изменение поля формы, которое симулятор заполняет вводом текста. Строгое чтение запрета «Поля формы: name, phone, email, purpose» → тип и способ ввода сохраняем.
- **`.btn-register`**: класс, количество и поведение существующих трёх кнопок в тарифах сохраняем. Новые CTA выше по странице делаем **обычными ссылками-якорями** (`a.btn`), а не `.btn-register`, чтобы не менять множество элементов, по которым работает симулятор.
- **Фиксированные/липкие панели не добавляем**: элемент с `position: fixed` может перехватывать клики симулятора по элементам под ним.

## Какие файлы/папки редактировать

- `index.php` — разметка и копирайт (кроме перечисленных запретов).
- `css/style.css` — оформление.
- `js/main.js` — клиентское поведение (обработчик `.btn-register` со скроллом к `#registration` сохраняется).
- `docs/researches/**` — артефакты анализа (требование `CLAUDE.md`).

Не трогаем: `api/**`, `sql/schema.sql`, `admin/**`, `Dockerfile`, `data/**`.

## Workflow после правок (из site_dir)

Из `STUDENTS.md`, пункты 7–9:

1. Внести изменения в страницу.
2. Нажать **Redeploy** в control-panel (данные в БД сбрасываются).
3. Снова запустить **Run visits simulator** (по умолчанию 100 визитов).
4. Сравнить конверсию до и после изменений.

Проверка результата: консоль симулятора, `https://<домен>/api/export.php`, админка `admin/orders.php` (пароль `FirstAid2026!`).

Локальный прогон для проверки вёрстки: `php -S 127.0.0.1:8765`, затем `curl http://127.0.0.1:8765/api/init.php`.
